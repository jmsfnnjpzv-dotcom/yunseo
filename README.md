# 윤서의 룩북 (ootw.yunseo)

정적 사이트입니다. 프레임워크 없이 HTML/CSS/JS만 사용합니다.
틀(화면 구조)과 내용(JSON·사진)이 나뉘어 있어서, 룩을 바꾸거나 더할 때는 `data/looks/`와 `img/`만 만지고 `tools/build.mjs`를 한 번 돌리면 됩니다.

## 새 룩 추가하는 법
1. `img/ep003/` 폴더에 사진 넣기: 큰 사진 `1.webp`(720×1280, 9:16), 같은 이름의 썸네일 `1-s.webp`(405×720). 룩이나 사진이 더 있으면 `2.webp`, `2-s.webp` …
2. `data/looks/003.json` 추가 (`002.json` 복사 후 수정, 칸은 아래 표)
3. 공유 미리보기 사진 만들기: 사이트에서 `tools/og.html?ep=003`을 열어 `og.jpg`를 내려받아 `img/ep003/og.jpg`로 넣기
   (아직 사이트에 안 올렸으면 저장소 폴더에서 `python3 -m http.server`를 켜고 `http://localhost:8000/tools/og.html?ep=003`)
4. 저장소 맨 위 폴더에서 `node tools/build.mjs` (Node 18 이상, 설치할 것 없음)
   - `looks/003/index.html`(카톡·DM에 그 룩의 제목·사진이 뜨는 EP 페이지)과 `data/looks/index.json`(룩 목록)을 만들어 줍니다. `index.json`은 이제 손으로 고치지 않습니다
   - JSON 칸과 글 규칙도 점검합니다. `!`는 경고(페이지는 만들어짐), `✗`는 그 EP를 건너뛴 것(홈에도 안 나옴)
5. 올리기

`build`를 안 돌리면 새 EP는 `index.json`에 없어서 홈에 안 나옵니다. 3번을 건너뛰면 미리보기 사진은 사이트 기본 `og.jpg`가 됩니다(나중에 넣고 다시 돌리면 바뀜).

## 주소
- EP 페이지: `looks/001/` (홈 카드가 여기로 갑니다. 공유는 이 주소로)
- 예전 주소 `look.html?ep=001`은 EP 페이지가 있으면 그리로 옮겨 가고, 없으면(build 전) 그 자리에서 그대로 보여 줍니다
- EP 페이지는 `look.html`을 틀로 만듭니다. `look.html`의 머리·꼬리를 고쳤으면 `build`를 다시 돌려 주세요

## JSON 칸 (`data/looks/NNN.json`)
| 칸 | 꼭 | 쓰이는 곳 |
|---|---|---|
| `id` | ✓ | `"003"`, 파일 번호와 같게 |
| `title` | ✓ | 브라우저 탭, EP 페이지 미리보기 제목(`EP.003 …`), 링크 전체 복사 글 |
| `cover` | ✓ | 첫 룩의 홈 썸네일 (`img/ep003/1-s.webp`) |
| `sets` | ✓ | 룩 목록 (아래 표). 하나면 한 룩, 여러 개면 LOOK 1·2·3 |
| `date` | | `"2026-10-27"` → 카드·상세에 `10.27` |
| `headline` | | 상세 큰 제목, `\n`으로 줄바꿈 (없으면 `title`). 미리보기 사진에도 그대로 |
| `summary` | | 미리보기 설명(`AI 가상인물 윤서의 데일리룩 · ` 뒤에 붙음) |
| `description` | | 상세 끝 '윤서의 메모' 글 |
| `tags` | | 상황 태그: 룩 지도와 메모의 `#태그` |
| `weather` | | `{"temp": "12–19°C", "note": "맑고 선선한 날"}` |
| `palette` | | `[["크림", "#f3ece1"], …]` 메모의 색 점 |
| `instagram` | | 인스타 게시물 주소 (메모 끝 '인스타에서 보기' 사진 카드) |
| `instagramThumb` | | 그 카드의 작은 사진 (`img/ep003/ig-post.webp`, 192×256 webp). 없으면 `cover` |
| `ogImage` | | 미리보기 사진을 다른 파일로 쓰고 싶을 때만. 없으면 `img/ep003/og.jpg` → 그것도 없으면 `og.jpg` |
| `youtubeId`, `loopMp4` | | 보통은 룩(`sets`)마다 적습니다. 여기 적으면 첫 룩에 붙습니다(룩이 하나인 EP용) |

`sets` 안의 룩 하나:
| 칸 | 꼭 | 쓰이는 곳 |
|---|---|---|
| `name` | ✓ | 룩이 여러 개면 `"LOOK 1 · 크림 × 브라운"`처럼. `·` 뒤가 홈 카드 제목 |
| `image`, `alt` | ✓ | 큰 사진과 대체 글 (홈 썸네일은 같은 이름에 `-s`) |
| `items` | ✓ | 아이템 목록 (아래 표) |
| `mood` | | 사진 아래 한 줄 |
| `tags` | | 그 룩만의 상황 (없으면 EP의 `tags`) |
| `extra` | | 옆으로 더 넘겨 볼 사진 `[{"image", "alt"}]` |
| `reel` | | 그 룩의 인스타 릴스 주소 (룩 이름 아래 '릴스로 보기' 사진 카드, 재생 표시) |
| `reelThumb` | | 그 카드의 작은 사진 (`img/ep003/ig-reel-1.webp`, 192×256 webp). 없으면 그 룩 사진의 `-s` |
| `youtubeId` | | 그 룩의 유튜브 쇼츠. 11자 영상 번호나 쇼츠 주소를 그대로. 비어 있으면 '▶ 쇼츠' 알약·플레이어가 아예 안 나옴 |
| `loopMp4` | | 소리 없이 반복되는 짧은 영상(`img/ep003/1-loop.mp4`, H.264, 1~2MB). 있으면 첫 사진 자리에서 화면에 보일 때만 재생, 못 틀면 사진 |

`items` 안의 아이템 하나:
| 칸 | 꼭 | 쓰이는 곳 |
|---|---|---|
| `cat`, `name` | ✓ | 왼쪽 분류, 상품 이름 |
| `url` | ✓ | 상품 링크(https). 비워 두면 화면에도, 개수에도 안 들어갑니다(쿠팡·무신사 빈 자리) |
| `shop` | | `에이블리`·`쿠팡`·`무신사` → 오른쪽 `에이블리 ↗`. 링크 주소로 알아볼 수 있으면 주소가 우선 |
| `similar` | | `true`면 갈색 '비슷한 상품' (사진 속 옷과 같은 상품이 아닐 때) |
| `color` | | 색 이름. 홈 룩 지도의 색 묶음 표(`assets/home.js`의 `COLORS`)에 있어야 컬러 칩에 잡힙니다 |
| `note` | | 사진과 실물이 눈에 띄게 다를 때 붙는 안내 (예: 트렌치 칼라) |

칸이 빠지면 그 줄만 안 나오고 화면은 그대로 나옵니다.

## 쇼츠 붙이기
1. 유튜브에 쇼츠를 올린 뒤 주소(`youtube.com/shorts/…`)를 그 룩의 `youtubeId`에 붙여 넣고 `build`
2. 사진 왼쪽 아래 '▶ 쇼츠'를 누르면 같은 칸이 플레이어로 바뀝니다(youtube-nocookie). 자동재생이 막힌 앱 안 브라우저에서는 플레이어의 재생 버튼 한 번
3. 홈 카드의 EP 배지에 `▶`가 붙습니다(따로 누르는 곳은 없음)

올리기 전 점검 (사이트는 플레이어 아래 줄에 '가상인물'을 늘 띄우지만, 영상만 따로 퍼져도 알 수 있게):
- 영상 안에 '가상인물 · 광고' 표시가 처음부터 끝까지 보이는지
- 업로드할 때 '변경되거나 합성된 콘텐츠'를 '예'로
- 설명란 첫 줄에 광고 문구
- 다른 앱 워터마크, 들린 치마·코트 같은 노출 변형이 없는지

## 룩 지도 (홈의 상황·컬러·아이템 칩)
JSON에서 저절로 만들어집니다. 룩이 하나도 없는 칩과 모든 룩에 다 있는 칩(눌러도 그대로)은 나오지 않습니다. 칩을 고르면 주소 끝에 `#컬러:브라운`처럼 남아서 그 주소를 공유하거나 상세의 `#태그`를 누르면 같은 상태로 열립니다.
- 상황: `tags` (카페 · 데이트 · 주말 · 산책 · 저녁약속 · 하객 · 여행). 세트에 `tags`를 넣으면 그 룩만의 상황, 없으면 EP의 `tags`
- 컬러: 아이템 `color`를 색 묶음으로 모읍니다. 표(`assets/home.js`의 `COLORS`, 예: 연청·진청 → 블루)에 없는 색 이름은 지도에 안 나오니 새 색이 나오면 표에 더합니다(`build`가 알려 줌)
- 아이템: 아이템 `cat` 그대로 (순서는 `home.js`의 `ITEMS`)
- 기온 칩은 아직 없습니다. 계절이 섞여 기온대가 갈릴 때 더하고, 그 전에는 소개 문구에 '기온별'을 쓰지 않습니다

## 사진 바꾸기
- 같은 파일 이름으로 덮어쓰면 끝 (`img/ep001/1.webp`, `1-s.webp` …). 첫 룩 사진이나 제목을 바꿨다면 미리보기 사진(`og.jpg`)도 다시 만들고 `build`
- 사진 비율은 `assets/site.css` 맨 위 `--ratio` 한 곳 (지금 `9/16`, 캠코더 스틸·릴스 비율. 3:4 사진으로 바꾸면 `3/4`)
- 인스타 카드 사진(`ig-*.webp`): 릴스 표지나 게시물 첫 사진을 3:4로 잘라 192×256 webp(품질 72, 10KB 안쪽). 영상 생성 도구의 워터마크가 보이는 장면은 쓰지 않습니다
- `og.jpg`(1200×630, 맨 위 폴더)는 홈 주소를 붙였을 때의 미리보기, `img/epNNN/og.jpg`는 그 EP 주소의 미리보기. 카톡은 JPG·PNG를 읽고 2:1로 잘라 보여 줍니다

## 공유 미리보기가 안 바뀔 때
카톡은 한 번 읽은 주소의 미리보기를 한동안(약 1시간) 기억합니다. 카카오 개발자 사이트의 '카카오톡 URL 메타정보 관리'(공유 디버거, https://developers.kakao.com/tool/debugger/sharing)에서 그 주소를 넣고 캐시를 지운 뒤 다시 붙여 보세요. 주소 끝 `/` 유무도 다른 주소로 봅니다(공유는 `looks/003/`처럼 `/`까지).

## 고지 (광고·가상인물) — 지우지 않는 것
문구는 `assets/look.js` 맨 위 `AD`(에이블리 광고 문구), `AD_COUPANG`(쿠팡 문구), `AI_NOTE`(가상인물 문구) 한 곳에서 바꿉니다.
- 상세 머리, 날씨 줄 바로 아래 옅은 상자: 광고 문구 → (쿠팡 링크가 실제로 있을 때만) 쿠팡 문구 → "윤서는 AI로 만든 가상인물이에요." 3줄 안쪽으로 둡니다(쿠팡 문구가 붙으면 그만큼 길어짐)
- 사진마다 오른쪽 위 '가상인물' 배지. 쇼츠를 틀면 플레이어는 덮지 않고 그 아래 줄에 '가상인물'
- 아이템 상자 머리 '광고 · 구매하면 수수료'(쿠팡 아이템이 있는 룩은 그 아래 쿠팡 문구), 상자 끝 "사진은 AI 이미지라 색·디테일·핏이 다를 수 있어요."
- '아이템 링크 전체 복사'로 복사한 글 첫 줄: 광고 문구(+쿠팡 문구), 가상인물 문구, 그다음 EP 주소와 링크
- 홈 소개 문장의 'AI로 만든 가상인물', 모든 페이지 footer 두 줄, EP 미리보기 사진의 'AI 가상인물' 표시와 설명 첫머리

## 글 규칙
- 윤서는 가상인물이라 직접 입어 본 듯한 말은 쓰지 않습니다: "입어 보니", "따뜻해요", "정사이즈", "핏이 좋아요" 같은 보온·핏·사이즈 후기 대신 스타일링 제안("~한 날엔 ~와 같이")이나 상품 정보("실물은 스탠드 칼라")로
- 수능·빼빼로데이 표현은 쓰지 않습니다
- `build`가 제목·소개·메모·무드·note에서 위 표현을 찾아 경고합니다(전부 잡지는 못하니 최종 확인은 눈으로)

## 링크
- 상품 링크는 에이블리 크리에이터 앱링크(제품별 개별 링크)가 1순위. 쿠팡·무신사는 가입 전이라 빈 자리만 둡니다(`shop`만 적고 `url`은 비움)
- 가격은 넣지 않습니다 (바뀌면 틀린 가격이 남음)
- 같은 상품이 여러 EP에 나오면 `note`·`similar`도 같은 사실로 맞춥니다
